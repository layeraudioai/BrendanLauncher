# Vite web apps and native Switch ports

BrendanLauncher supports two distinct targets from a web-app source folder:

1. Vite production assets (`dist/`) for normal browser rendering.
2. An ABI-3 native Switch app package generated by WebPort v1 for the supported
   subset documented below.

Vite itself only bundles browser code; the Switch-side app does **not** execute
that JS bundle or provide a browser/DOM. WebPort reads the source HTML and
selected CSS, generates native C using BrendanLauncher's SDK renderer/input
APIs, then cross-compiles it with `sdk/tools/hbx-build.py`. Unsupported DOM,
JavaScript, CSS, browser APIs, images, and network behaviors are not silently
run on the console: implement them natively or extend WebPort first.

## Build and port to Switch

Requirements: Node.js, npm, Python 3, and the AArch64 toolchain required by the
HBX SDK. First build installs the app-local Vite dependency (npm network access
is needed if it is not already installed).

```sh
node tools/build-webapps.cjs hello-vite --install
node tools/port-webapp.cjs hello-vite
```

The second command generates `apps/hello-vite-native/manifest.json` and
`src/app.c`, then compiles the ABI-3 app into its `build/` package. Refresh the
Switch app library to find **Hello TypeScript web app**. The launcher panel's
**Web apps → Build Switch app** action runs the same port step. The AIO build
runs the example port automatically.

To only inspect/generated-source-test without a cross compiler:

```sh
node tools/port-webapp.cjs hello-vite --skip-vite --no-build
```

`--skip-vite` assumes `dist/index.html` already exists. `--no-build` emits
native source but does not create a launchable package.

## WebPort v1 supported subset

- Source `index.html` with one `<h1>` or `<h2>` title.
- Up to 12 `<p>` paragraphs and 6 `<button>` controls.
- Basic CSS color declarations on `body`, `.card`, `main`, `h1`, `h2`, `p`,
  and `button`; supports hex and `rgb()/rgba()` colors.
- Controller D-pad selection, A activation, touchscreen button selection/activation,
  and B/Plus exit.
- Buttons annotated `data-native-action="counter"` map to a native counter
  action. The same HTML/TypeScript can still have normal browser behavior.

Opt in with `nativePort` in `webapp.json`:

```json
"nativePort": {
  "enabled": true,
  "version": 1,
  "actions": ["counter"]
}
```

The compiler requires action markers to use declared, implemented actions. It
currently rejects unsupported marked actions, and generated app packages are
marked as generated so the tool will not overwrite a hand-written app folder.
The example in `web-apps/hello-vite/` demonstrates this path.

## Browser target / Node server apps

Vite assets may also be served by the local host panel in a desktop browser.
The panel can supervise `runtime: "node"` server apps using the provided
`HOST=127.0.0.1` and allocated `PORT`. Those Node apps run with the desktop
user's permissions and are not sandboxed; only run trusted code. Host-browser
serving is independent of the native Switch port.

## Switch2Brew compatibility

Switch2Brew is not a Switch homebrew runtime. Its server hardcodes privileged
HTTP port 80 and starts a DNS server on port 53 with DNS redirection. It cannot
be used unchanged as either a Node web app or a native WebPort app.
